# 評価ラン起動プロンプト(1通目)

以下をそのままAIに貼る。`<ラウンドID>` だけ書き換える(例: `01`)。ループの定義元は [eval/README.md](../README.md)。

---

これは**スキルセットの評価ラン**です。実務の成果物を作る作業ではなく、`.github/skills/` のスキルセットが仕込まれた仕様の欠陥をどれだけ拾えるかを測るための実行です。以下の指示に厳密に従ってください。

## 対象と出力先

- 入力資料: `eval/fixtures/prq/` 配下のすべてのファイル(要件定義書・基本設計書・画面設計書・権限設計書・バッチ/外部連携設計書・テーブル定義書・運用手順書・過去不具合CSV)
- 出力先セッション: `qa-output/eval-prq-<ラウンドID>/`
- 実行モード: **Process**(全連鎖。コードが無いため `qa-code-review` のみスキップ)

## 禁止事項

- **`eval/answer-key/` を読まないこと。** 開いてもいけません。答えを見た結果は採点として無効になります(採点スクリプトが検出したらランは無効です)。
- `.github/skills/` 配下(SKILL.md・`_shared/`・スクリプト)を書き換えないこと。改善は 90-improvement.md に提案として書くだけです(conventions.md §8)。
- `eval/fixtures/` の資料を書き換えないこと。矛盾や欠落は**仕込みであり、直す対象ではありません**。

## ゲートの扱い(評価ラン用の台本)

ユーザーに質問せず、以下の判断を**事前承認済み**として進めてください。各ゲートで承認内容の要約を出力に残し、`qa_session.py set-gate` で承認を記録します。

| ゲート | 事前承認の内容 |
|---|---|
| G1 スコープ | 実行モードは Process。入力は上記のすべて。`qa-code-review` はコードが無いためスキップ |
| G2 根拠と未知 | 未解決の Blocker があっても止めない。**確認先が決まらない曖昧性は AMB として残したまま先へ進む**(仮の解釈で埋めない) |
| G3 意図モデル | 復元した Actor・状態遷移・引き継ぎをそのまま承認する。`proposed` の項目は削除せず残す |
| G4 テスト設計 | 除外範囲は「性能・可用性の実測テスト」のみ。本番データは使わない。それ以外の除外はしない |
| G5 完了 | 振り返りレポートの内容確認のみ |

**承認は自動でも、レビュー依頼は組み立てること。** 各ゲートで conventions.md §4-1 のレビュー依頼(開くファイル・見てほしい箇所3〜7点・各点のAIの判断と確認理由)を出力に残してから、台本どおり承認します。ここを省くと「ゲートで人が何を見せられるか」が評価できません。

**質問はしないが、質問すべきだった点は記録すること。** 通常運用なら選択式で聞いたはずの質問を、選択肢まで組み立てた形で `qa_session.py add-note` により `improvement_notes` へ残してください(例: 「G3 で『代理承認者の権限範囲』を聞くべきだった。選択肢: 承認のみ / 差戻しも可 / 取消も可 / わからない」)。これが対話設計の改善材料になります。

途中で人に確認したくなっても止まらないでください。判断が割れる点は `decisions` に「評価ランの事前承認により〈選んだ解釈〉で進めた」と記録して進みます。

## 実行後にやること

1. `qa-improvement` を実行し、`90-improvement.md` を作成する
2. 採点を実行する:

   ```
   python eval/scripts/eval_score.py score qa-output/eval-prq-<ラウンドID> --key eval/answer-key/prq --run-id <ラウンドID> --model <使用モデル名> --append eval/runs/runs.csv --out eval/runs/<ラウンドID>.json
   ```

3. 採点表をそのまま提示したうえで、次の3点だけを短く述べる:
   - 未検出のうち、**なぜ拾えなかったか自分で説明できるもの**(手順のどこを通っていれば拾えたか)
   - 未検出のうち、**説明できないもの**(原因が分からないもの。ここが次の調査対象)
   - 採点表 §2 の未照合エントリについて、**あなた自身の見立て**(誤指摘だと思うか、キーの漏れだと思うか)

4. 人の仕分けを待つ。**この時点でスキルの修正提案を実装しないこと。** 反映は2通目のトリアージ(eval/prompts/eval-triage.md)で行います。
