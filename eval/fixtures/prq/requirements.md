# 購買申請システム(PRQ)要件定義書

| 項目 | 内容 |
|---|---|
| 文書番号 | PRQ-REQ-001 |
| 版数 | v1.2 |
| 作成日 | 2026-02-10 |
| 最終更新 | 2026-04-18 |
| 承認者 | 調達部長 / 情報システム部長 |
| 対象システム | 購買申請システム(社内呼称: PRQ) |

## 1. 背景と目的

株式会社カナメ製作所(従業員約1,200名、製造業)では、消耗品・工具・外注役務の購買を、紙の購買依頼票とExcel台帳で運用している。年間の購買申請は約9,000件。

現行運用には次の課題がある。

- 申請書が承認者の机で滞留し、申請者が進捗を追えない(平均リードタイム 6.4営業日)
- 承認金額の基準が部門ごとに解釈されており、二段階承認の運用が統一されていない
- 検収の記録が紙のため、会計システムへの計上が月末に集中する
- 過去の購買実績を横断的に検索できず、同一品目の重複購買が発生している

本システムは、購買申請から検収・会計計上までを電子化し、申請の進捗可視化と承認基準の統一を実現する。

## 2. 対象範囲

| 区分 | 内容 |
|---|---|
| 対象 | 消耗品・工具・外注役務の購買申請、承認、発注、検収、会計計上連携 |
| 対象外 | 資産計上を伴う設備投資(別途、設備投資稟議システムで運用) |
| 対象外 | 原材料の定期発注(基幹システム KANAME-MRP が自動発注する) |
| 対象外 | 支払処理・請求書照合(会計システム ACC の機能) |

## 3. 登場者と役割

| ロール | 所属 | 業務上の役割 |
|---|---|---|
| 申請者 | 全部門の社員 | 購買申請を起票し、納品後に検収を登録する |
| 承認者 | 各部門の部門長 | 自部門の申請を承認・差戻しする |
| 上位承認者 | 調達部長 | 高額申請の二段階目の承認を行う |
| 購買担当 | 調達部 | 承認済み申請の発注先を確定し、発注を確定する |
| 経理担当 | 経理部 | 月次締めを実行し、会計計上を確認する |
| システム管理者 | 情報システム部 | マスタ保守、代理承認者の設定支援 |

## 4. 業務要件

### 4.1 申請

| ID | 要件 |
|---|---|
| FR-01 | 申請者は購買申請を起票できる。起票直後の申請は下書き状態で保存され、申請者本人のみが参照できる |
| FR-02 | 申請には、件名・希望納期・購買理由・明細(品目名・数量・単価)・予算科目を入力する |
| FR-03 | 申請者は下書きを提出し、承認依頼を行える。提出時に必須項目の充足を検証する |
| FR-04 | 申請者は、提出後・承認前の申請を取り下げできる |

### 4.2 承認

| ID | 要件 |
|---|---|
| FR-05 | 承認者は、自部門の申請を承認または差戻しできる。他部門の申請は参照も承認もできない |
| FR-06 | 1件あたり税抜10万円**以上**の申請は、部門長の承認に加えて調達部長の承認を要する(二段階承認) |
| FR-07 | 差戻しを受けた申請者は、内容を修正して再提出できる |
| FR-08 | 部門長が不在の期間は、代理承認者を設定できる。代理承認者は不在期間中に限り承認を行える |

### 4.3 発注・検収

| ID | 要件 |
|---|---|
| FR-09 | 購買担当は、承認済みの申請に発注先・発注単価を設定し、発注を確定できる |
| FR-10 | 発注が確定した申請は、翌営業日までにサプライヤへ発注情報が送信される |
| FR-11 | 申請者は、納品された品目の検収を登録できる。検収日は登録日を既定とし、過去日への変更を許可する |
| FR-12 | 検収が完了した申請は、会計システム ACC へ仕訳データとして連携される |

### 4.4 進捗と通知

| ID | 要件 |
|---|---|
| FR-13 | 申請者は、自分の申請の現在状態と、次に誰の対応待ちかを一覧で確認できる |
| FR-14 | 状態が変化したとき、次に対応すべき担当者へメール通知する |
| FR-15 | 承認待ちのまま14日を経過した申請は、自動的に失効する |

## 5. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| NFR-01 | 性能 | 申請一覧の表示は、1,000件の検索結果に対して3秒以内 |
| NFR-02 | 可用性 | 平日 07:00〜22:00 を稼働時間とする。夜間バッチ実行中の参照は許容する |
| NFR-03 | 監査 | 申請の状態変化と承認操作は、操作者・日時とともに監査ログに記録する。保存期間は7年 |
| NFR-04 | 権限 | 権限はロールベースで制御する。権限のない操作は画面に表示しない |
| NFR-05 | 移行 | 現行Excel台帳の過去2年分(約18,000件)を参照専用データとして移行する |

## 6. 業務ルール

| ID | ルール |
|---|---|
| BR-01 | 申請金額は税抜で扱う。消費税は会計システム側で計算する |
| BR-02 | 予算科目は、申請者の所属部門に紐づく科目のみ選択できる |
| BR-03 | 会計計上は検収日の属する月度で行う。月次締めは翌月第5営業日に経理が実行する |
| BR-04 | 発注済みの申請は、サプライヤへの発注情報送信後は取り消せない |
| BR-05 | 申請の起票者と承認者は、監査上の理由により分離する |

## 7. 用語

| 用語 | 定義 |
|---|---|
| 申請 | 購買を依頼する1件の記録。1件に複数明細を持つ |
| 明細 | 申請に含まれる品目の1行。品目名・数量・単価を持つ |
| 検収 | 納品物が発注内容どおりであることを確認し、記録する行為 |
| 月度 | 会計上の期間。当月1日から末日まで。年度は4月開始 |
| 代理承認者 | 承認者の不在期間中に承認を代行する者 |

## 8. 制約・前提

- 会計システム ACC への連携はファイル連携(CSV)とし、日次で実行する
- サプライヤへの発注情報送信は、既存のEDIゲートウェイを経由する
- 認証は社内Active Directoryのシングルサインオンを利用する
- 部門・社員・上長関係のマスタは人事システムから日次で同期する
