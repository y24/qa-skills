# 購買申請システム(PRQ)バッチ・外部連携設計書

| 項目 | 内容 |
|---|---|
| 文書番号 | PRQ-BAT-001 |
| 版数 | v1.3 |
| 最終更新 | 2026-07-10 |
| 関連文書 | PRQ-BD-001(基本設計書 v2.0) |

## 1. バッチ一覧

| バッチID | 名称 | 実行時刻 | 処理対象 |
|---|---|---|---|
| BATCH-01 | 承認待ち自動失効 | 毎日 02:00 | `submitted` の申請 |
| BATCH-02 | EDI発注送信 | 毎日 19:00 | `ordered` かつEDI未送信の申請 |
| BATCH-03 | 会計連携(仕訳出力) | 毎日 03:00 | `received` の申請 |
| BATCH-04 | 人事マスタ同期 | 毎日 01:00 | 社員・部門・部門長 |
| BATCH-05 | 月次締め | 経理担当が画面から手動実行 | 対象月度の `closed` 申請 |

すべてのバッチはジョブ管理システム(JP1)から起動する。異常終了した場合は、原因を除去したうえで同一パラメータで再実行する。

## 2. BATCH-01 承認待ち自動失効

### 処理内容

1. `status = 'submitted'` の申請を抽出する
2. 提出日時(`submitted_at`)から**10営業日**を経過している申請を失効対象とする
3. 対象申請の状態を `expired` に更新し、監査ログに記録する
4. 申請者へ失効通知メールを送信する

### 補足

- 営業日は社内カレンダーマスタ(`business_calendar`)に従う。
- 差戻し後に再提出された申請は、再提出日時を起点として数え直す。
- 失効した申請は編集できない。

## 3. BATCH-02 EDI発注送信

### 処理内容

1. `status = 'ordered'` かつ `orders.edi_sent_at IS NULL` の申請を抽出する
2. サプライヤ別に発注データを生成し、EDIゲートウェイへ送信する
3. 送信に成功した申請の `orders.edi_sent_at` を更新する
4. 申請者へ検収依頼の通知メールを送信する

### 補足

- 1回の送信単位はサプライヤ単位。1サプライヤ分の送信が失敗した場合、そのサプライヤ分のみ翌日再送する。
- EDIゲートウェイの応答タイムアウトは60秒。タイムアウト時は未送信として扱う。
- バッチの実行時間は最大30分を見込む。

## 4. BATCH-03 会計連携(仕訳出力)

### 処理内容

1. `status = 'received'` の申請を抽出する
2. 申請1件につき1明細行の仕訳CSVを生成する(勘定科目は予算科目マスタから引く)
3. CSVを連携用共有フォルダへ配置し、状態を `closed` に更新する
4. 会計システム ACC は 05:00 にCSVを取り込む

### 仕訳CSVのレイアウト

| 列 | 内容 |
|---|---|
| 伝票日付 | 検収日 |
| 計上月度 | 検収日の属する月度(YYYYMM) |
| 借方科目 | 予算科目マスタの勘定科目コード |
| 金額 | 発注単価 × 検収数量の合計(税抜) |
| 摘要 | 申請番号 + 件名 |
| 部門コード | 申請者の所属部門 |

### 補足

- ACC 側で取り込みエラーになった場合、エラーリストがPRQへ返却される。返却されたエラーの再連携手順は運用手順書で定める。

## 5. BATCH-05 月次締め

### 処理内容

1. 経理担当が対象月度を指定して実行する(翌月第5営業日を想定)
2. 対象月度の `closed` 申請を集計し、締め済みとして `monthly_closings` に記録する
3. 締め済み月度への新規計上を抑止する

### 補足

- 締め済み月度に対して BATCH-03 が計上しようとした場合はエラーとし、当該申請を翌月度で計上する。
- 締め処理の取り消し(締め戻し)は、経理担当とシステム管理者の双方の操作を要する。

## 6. 外部連携インタフェース

| 連携先 | 方向 | 方式 | 頻度 | 障害時の扱い |
|---|---|---|---|---|
| 会計システム ACC | PRQ → ACC | CSVファイル | 日次 | 翌日の連携に含める |
| EDIゲートウェイ | PRQ → サプライヤ | EDI(XML) | 日次 | サプライヤ単位で翌日再送 |
| 人事システム | 人事 → PRQ | CSVファイル | 日次 | 前日のマスタで運用を継続する |

## 7. バッチ実行時の排他

- BATCH-01・BATCH-03 は、対象レコードを1件ずつ更新する(全件ロックは行わない)。
- BATCH-02 の実行中に対象申請が更新された場合の扱いは、詳細設計で定める。
- 稼働時間外(22:00〜07:00)のオンライン操作は想定しない。
